01 · Rola

Ręka agenta na rachunku demo

Moduł wystawia przez MCP odczyty rachunku (pozycje, zlecenia oczekujące, saldo, lista rachunków) i zapisy (złożenie, zamknięcie, korekta, anulowanie, przełączenie rachunku, doładowanie demo). Żadnych świec, cen ani wskaźników — rynek to archiwum market-data.

Trzy ograniczenia definiują moduł: tylko demo, sprawdzone u bramki (GET /capabilities musi odpowiedzieć environment == "demo" — bramka wyprowadza tę wartość z hosta, do którego jest przypięta, więc odpowiedź coś znaczy); jeden transport — strumieniowe HTTP, żadnego stdio, bo lokalnie odpalony proces nie niesie tożsamości rozmówcy; jeden rozmówca — lista allowed_applications w Terraformie ma dokładnie jeden wpis: tożsamość zarządzaną workbencha. Przeglądarka nigdy tu nie dzwoni.

Kontrola demo biegnie przed otwarciem portu — proces, który nie nasłuchuje, jest nieosiągalny, co jest mocniejszą gwarancją niż odmowa w pierwszym żądaniu.

02 · Start procesu

Cztery kroki, dwa powody odmowy

# __main__.py — _serve() robi dokładnie cztery rzeczy, po kolei
settings = Settings()                          # CAPITAL_GATEWAY_API_KEY bez domyślnej — brak = ValidationError
gateway = GatewayClient(settings)
await gateway.ensure_demo_environment()        # nie-demo → NotDemoEnvironment; bramka padła → GatewayUnavailable
await uvicorn.Server(config).serve()           # dopiero teraz otwiera się port 8060

main() nie przyjmuje żadnych argumentów i nie ma argparse — nie ma transportu do wybrania, a test źródłowy pilnuje, żeby grep za run_stdio_async nigdy nic nie znalazł. Klucz bramki jest wymagany także na loopbacku: bramka sprawdza nagłówek X-Gateway-Key u każdego rozmówcy.

05 · Ścieżka zapisu

Zapis wychodzi raz albo wcale

Droga zapisu: funkcja narzędzia → lokalna walidacja argumentów → _write → GatewayClient.write → jedno żądanie httpx → wynik. Bramka nie przyjmuje klucza idempotencji, więc powtórka nie jest potwierdzeniem — jest drugim zleceniem.

Powtórzone zlecenie to druga pozycja, nie potwierdzenie pierwszej.

Jedno rozróżnienie niesie całe bezpieczeństwo słowne: GatewayRefused.is_access_failure. 401, 403, 408, 429 i każde 5xx to „awaria dostępu — skutek na rachunku nieznany, odczytaj pozycje, nie powtarzaj”; 404 i 422 zostają odmową z nazwanym polem do poprawy. Powód zapisany w errors.py: 401 odczytane jako odmowa wysyła agenta w poprawianie zlecenia, na które nikt nigdy nie spojrzał.

Strażnicy lokalni przed żądaniem

place_order odmawia LIMIT/STOP bez poziomu i MARKET niosącego level lub good_till — bramka po cichu je upuszcza, a odczytany z powrotem poziom byłby ceną wykonania, więc nic w odpowiedzi nie zdradziłoby, że limit zignorowano. amend_stops odmawia ustawienia i wyczyszczenia tego samego stopu naraz.

REJECTED i PENDING dostawcy przeniesione dalej

Odrzucenie dostawcy staje się odmową narzędzia; zlecenie nierozliczone wychodzi jako outcome="unsettled" — bramka zdążyła już wydać swój budżet odpytywania potwierdzeń.

Poświadczenie nie wycieka nigdy

X-Gateway-Key podróżuje tylko na żądaniu wychodzącym; żaden typ wyjątku go nie niesie.

06 · Migawka kontraktu

Cały OpenAPI bramki, komitowany tutaj

scripts/contract.py trzyma w contract/capital-gateway.openapi.json migawkę całego dokumentu OpenAPI bramki. check generuje na nowo i pada na różnicy — zmiana kontraktu pokazuje się jako diff obok zmiany, która ją wywołała.

Generacja nie potrzebuje bazy, sesji u dostawcy ani poświadczeń — bramka buduje swoje Settings w lifespan, nie przy imporcie. Determinizm jest pilnowany świadomie: Python przypięty do 3.12 (3.13 zmienił frazę powodu HTTP 422, co wyglądałoby jak zmiana kontraktu), wymuszone UTF-8 (Windows psuł pauzy w opisach), posortowane klucze. Dlatego też w CI każda zmiana w całym module capital-gateway odpala job trading-mcp — dokument budują trasy i dekoratory rozsiane po module, więc nie ma węższego uczciwego filtra.

07 · Testy

Prawdziwy FastMCP, atrapa HTTP

Testy ćwiczą prawdziwą instancję FastMCP przez await mcp.call_tool(...) na zamockowanym respx HTTP — żaden test nie dotyka capital.com ani działającej bramki. Autouse'owy fixture czyści zmienne środowiskowe, żeby lokalny .env nie zmieniał wyników. Najcięższe testy strzegą ścieżki zapisu: „zapis nigdy nie jest ponawiany po 5xx”, „zapis nigdy nie jest ponawiany po timeoutcie”, „zapis kosztuje jedną rundę”, „401 to awaria dostępu, nie odmowa”. Dwa testy transportu monkeypatchują uvicorn.Server.serve i dowodzą, że przy nie-demo i przy niedostępnej bramce port nigdy nie został otwarty.
