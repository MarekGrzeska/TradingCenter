01 · Stan dziś

Czego nie sprawdza żadna obecna warstwa

Repozytorium ma dużo testów, ale każdy zatrzymuje się na jednej stronie styku. Nikt nie uruchamia terminalu przeciw działającemu workbenchowi.

Luka to szwy, nie reguły. Komentarze w kodzie same opisują błędy tej klasy:

Proxy archiwum nazywało się /archive, a tę samą ścieżkę miała zakładka. Test jednostkowy tego nie widzi, bo nie przechodzi przez serwer deweloperski.

Ładowanie ruszało przy imporcie, przed rozstrzygnięciem logowania. Widać to dopiero w prawdziwej kolejności uruchamiania strony.

Kolejność tras routers/runs.py

/runs/compare musi stać przed /runs/{run_id}. Dziś pilnuje tego test API. Test E2E złapałby też każdy podobny przypadek w trasach, których nikt nie przewidział.

Pętla agent → narzędzie → edytor strategie

draft_strategy zapisuje szkic w bazie strategii, a terminal czyta go po turze. Każda połowa ma swój test, ale całego obiegu nie sprawdza nic.

02 · Zakres

Zasady z CLAUDE.md („How much test is enough”) obowiązują i tutaj: reguła domeny jest testowana raz, w najniższej warstwie. Warstwa E2E nie powtarza macierzy z pytest ani z vitest.

03 · Architektura

Osobny stos obok stosu deweloperskiego

Stos E2E ma własne porty, własną bazę w pamięci i własny katalog roboczy. Może działać obok uruchomionego scripts/dev.py i nie dotyka ani bazy z archiwum, ani pliku .env z kluczami.

Porty 15173, 18030 i 55442 trzeba dopisać do listy portów w CLAUDE.md jako „tylko E2E”, bo dziś plik wymienia każdy port, który jest czyjś. Logowanie nie jest potrzebne: terminal bez VITE_ENTRA_* ma tożsamość unconfigured i nie prosi o nic, a workbench bez SERVER_MODE nie wymaga tokenu.

04 · Zero płatności

Cztery bariery przed tokenem, za który się płaci

Każda z nich wystarczy sama. Są cztery, bo pomyłka w jednym pliku nie powinna kosztować.

1. Model to scenariusz bez sieci

AGENT_PROVIDER=sim podstawia dostawcę, który odpowiada z pliku i nie otwiera żadnego połączenia. Odmawia startu tam, gdzie ustawiono DATABASE_USER, jak już dziś symulacja pakietu YouTube.

2. Fikcyjne klucze 401

.env stosu E2E ma wszystkie *_OPENAI_API_KEY ustawione na sk-e2e-nie-placi. Gdyby scenariusz się nie włączył, OpenAI odrzuci zapytanie bez naliczenia opłaty.

3. Adres OpenAI donikąd ECONNREFUSED

OPENAI_BASE_URL=http://127.0.0.1:9/v1. Biblioteka openai 3.3 czyta tę zmienną, a langchain-openai 1.5 ją respektuje (sprawdzone w zainstalowanych wersjach). Zapytanie kończy się na własnym komputerze.

4. Prawdziwy .env nie jest czytany katalog

Każda konfiguracja workbencha czyta .env z bieżącego katalogu (env_file=".env"). Stos E2E uruchamia proces z e2e/stack, więc plik z prawdziwymi kluczami w modules/workbench nigdy nie trafia do procesu.

Z tego samego powodu stos nie składa zleceń i nie zużywa budżetu zapytań Capital (10/s na rachunek, wspólny z działającym stosem dev): bez TRADING_MCP_URL rozmowa nie ma narzędzi rachunku, a bramka nie jest uruchomiona.

Scenariusz dopasowuje wiadomość operatora wyrażeniem regularnym i odtwarza kroki: wywołania narzędzi i tekst. Nazwane grupy trafiają do argumentów, więc jeden statyczny plik obsłuży strategię o dowolnym numerze, bez zapisywania scenariusza w trakcie testu:

// e2e/stack/agent-scenario.json — czytany przez AGENT_SIM_SCENARIO
{ "turns": [
  { "when": "^E2E szkic (?<id>\\d+): stop 1,5 ATR$",
    "steps": [
      { "tool": "draft_strategy",
        "arguments": { "strategy_id": "{id}", "document": { /* dokument ze stopem 1.5 ATR */ } } },
      { "say": "Wpisałem stop 1,5 ATR do edytora." } ] },
  { "when": ".*", "steps": [ { "say": "(scenariusz E2E: brak dopasowania)" } ] } ] }

Narzędzie wykonuje się naprawdę: draft_strategy waliduje dokument i zapisuje szkic w bazie strategii, a terminal czyta go po turze tak samo jak w produkcji. Zastąpiony jest tylko wybór, co powiedzieć. Scenariusz zgłasza zerowe zużycie tokenów, więc zakładka kosztów nie pokaże żadnego wydatku.

06 · Dane

Pusta baza, migracje aplikacji i wygenerowane świece

  1. Baza od zera przy każdym uruchomieniu. Kontener na tmpfs, role i bazy z docker-entrypoint-initdb.d, które przy pustym wolumenie wykona się za każdym razem.
  2. Migracje robi workbench w swoim lifespan, jak na produkcji. E2E sprawdza więc przy okazji stałą regułę „merge zostawia produkcję działającą”: każdy łańcuch migracji od pustej bazy.
  3. Seed archiwum skryptem w projekcie workbencha: para US100 (minuty i godziny), ok. 30 dni świec z losowego spaceru z ziarnem (builder z tests/strategies/market.py) i zakres pokrycia. Backtest na takich danych kończy się w sekundach.
  4. Koszty przez profil operatora (PUT /costs/US100) zamiast brokera, bo bramki nie ma. Pobranie kosztów z capital.com zostaje w scenariuszach ręcznych (B-02, B-03).
  5. Każdy test tworzy własną strategię z unikalną nazwą. Przygotowanie idzie przez REST (request Playwrighta przez proxy Vite), a klikanie dotyczy tylko tego, co test sprawdza.

Przykład testu. Przygotowanie idzie przez REST, a sprawdzenie przez ekran, po rolach i polskich etykietach, które widoki już mają:

// modules/terminal/e2e/tests/backtests.spec.ts
test("porównuje dwa uruchomienia obok siebie", async ({ page, request }) => {
  const id = await createStrategy(request, "porównanie");
  const [a, b] = await Promise.all([finishedRun(request, id, { stop: 2 }), finishedRun(request, id, { stop: 3 })]);

  await page.goto(`/backtests?strategy=${id}`);
  await page.getByRole("checkbox", { name: `Porównaj uruchomienie ${a}` }).check();
  await page.getByRole("checkbox", { name: `Porównaj uruchomienie ${b}` }).check();
  await page.getByRole("button", { name: "Porównaj (2)" }).click();

  const table = page.getByRole("table", { name: "Porównanie" });
  await expect(table.getByRole("columnheader", { name: new RegExp(`#${b}`) })).toBeVisible();
});

Edytor to CodeMirror, czyli contenteditable: fill() go nie obsłuży. Pomocnik typeInEditor() klika .cm-content, zaznacza całość skrótem i wpisuje tekst przez keyboard.insertText. Jedno miejsce, jeden haczyk.

08 · Uruchamianie

Jedno polecenie, które sprząta po sobie

Z modules/terminal: pnpm e2e. Skrypt scripts/e2e.py korzysta z gotowych części scripts/dev.py: nadzoru procesów, czekania na HTTP i zamykania drzewa procesów na Windows, które jest już tam rozwiązane.

  1. Podnosi kontener tradingcenter-e2e-db (55442, tmpfs) i czeka na pg_isready.
  2. Uruchamia workbench na 18030 z katalogu e2e/stack i czeka na /health: migracje wszystkich łańcuchów od zera.
  3. Wgrywa seed: świece, parę i profil kosztów.
  4. Woła pnpm exec playwright test. Playwright sam stawia Vite na 15173 (webServer, reuseExistingServer: false), żeby nigdy nie trafić w stos dev.
  5. Zawsze zamyka workbench i usuwa kontener. Flaga --keep zostawia stos do debugowania w playwright test --ui.

08a · Faza 0

Wynik próby: da się, i szybko

Stos E2E wstaje obok stosu dev potwierdzone

Kontener tradingcenter-e2e-db na 55442 (55433 zajmuje kontener innego projektu, market-data-db-1), workbench na 18030 z katalogu e2e/, Vite na 15173. Stos dev na 55432 i 8030 nietknięty.

Archiwum bez bramki podaje świece z seeda ryzyko zamknięte

Para US100 widoczna w /market/pairs (30 240 świec, stan kolekcji unknown). Backtest strategii godzinowej przez REST: zakończony po ok. 3 s, 14 transakcji, koszty z profilu operatora. Atrapa bramki nie jest potrzebna.

Bariera 3 działa sprawdzone

Tura rozmowy bez scenariusza kończy się zdarzeniem the model call failed, a w logu jest openai.APIConnectionError. Zapytanie nie wyszło poza komputer.

ST-01 przechodzi 1 test

Strategia założona przez REST, otwarta z listy; widać edytor z dokumentem, czat strategii i numer rewizji. Bez żadnej zmiany w kodzie terminalu ani workbencha.

Dwie poprawki konfiguracji do szkieletu

Stawki w katalogu modeli muszą być dodatnie (walidacja odrzuca zero), więc E2E ma 0,001. Projekt workbencha nie jest instalowanym pakietem, więc seed i workbench potrzebują PYTHONPATH albo --app-dir. Vitest dostał jawne include: src/**/*.test.*, żeby nie zbierał testów Playwrighta.

08b · Faza 1

Szkielet i 14 testów: pierwszy znaleziony błąd

pnpm e2e stawia stos, wgrywa seed, uruchamia 14 testów (ST-01…06, BT-01…08) i sprząta. Całość trwa około minuty: same testy 41 s.

Znaczniki walidacji nie pojawiały się po przerwie w pisaniu naprawione

ST-02 nie przeszedł za pierwszym razem: streszczenie mówiło „Dokument ma problemy”, ale edytor nie zaznaczał emaa. forceLinting z @codemirror/lint uruchamia tylko lint, który jeszcze czeka, a ten po ostatnim naciśnięciu klawisza dawno się wykonał, zanim walidacja odpowiedziała. Edytor podaje teraz znaczniki sam (setDiagnostics). Test jednostkowy w jsdom tego nie widział. Scenariusz ręczny E-01 wymagał tego zachowania.

Przygotowanie przez REST, sprawdzenie na ekranie support.ts

Strategie, rewizje i zakończone uruchomienia powstają przez proxy Vite, tak jak woła je terminal. Każdy test ma własną strategię, więc kolejność testów nie ma znaczenia.

Nic z powłoki nie przechodzi do workbencha scripts/tests/test_e2e.py

Środowisko procesu to lista dozwolonych nazw systemowych plus workbench.env. Testy pilnują, że klucz z powłoki dewelopera nie dociera do workbencha, każdy klucz modelu w pliku jest atrapą, a każda baza to kontener E2E.

08c · Faza 2

Agent na scenariuszu: 18 testów i drugi błąd

Zmiana OpenSpec agent-sim-provider dodała AGENT_PROVIDER=sim: rozmowa odpowiada z e2e/agent-scenario.json, a narzędzia działają naprawdę. Doszły testy AG-01…04; cały zestaw to 18 testów w ok. 75 s.

Wybór modelu wracał do Luny po ponownym otwarciu naprawione

AG-03 nie przeszedł: rozmowa działała na wybranym modelu, ale po przeładowaniu albo ponownym otwarciu strategii wybierak pokazywał pierwszy model z katalogu. Rozmowa otwierała się, zanim przyszła lista rozmów, z której store brał model, i nikt potem tego nie poprawiał. Teraz model otwartej rozmowy jest brany, gdy lista przyjdzie. To ten sam objaw, który operator zgłosił 25.10 w czacie strategii.

Zero tokenów, nie „nieznane” agent-usage

Każde symulowane wywołanie zostawia wiersz zużycia z zerem; zakładka kosztów nie pokazuje wydatku ani wierszy nieznanych.

10 · Ryzyka

Co może pójść źle

Archiwum bez bramki faza 0

Śledzona para będzie próbować dociągnąć dane z 127.0.0.1:9. Jeśli to ukryje parę albo jej świece, zapasem jest mała atrapa bramki z historią i warunkami instrumentu. Dałaby przy okazji test pobrania kosztów od brokera.

Niestabilne testy asynchroniczne utrzymanie

Uruchomienia liczą się w tle. Zamiast sleep testy używają expect.poll i automatycznego czekania lokatorów, a małe dane trzymają backtest w sekundach. trace: retain-on-failure pokazuje, co było na ekranie.

Rozrost zestawu koszt utrzymania

E2E jest najdroższą warstwą w utrzymaniu. Limit: jedna ścieżka na funkcję, 15–25 testów na obszar. Nowy wariant reguły to test w pytest albo vitest, nie tutaj.

Dwa uruchomienia naraz worktree

Porty E2E są stałe, tak jak porty dev, więc jeden stos E2E naraz na maszynie. Stos dev może działać obok.

Przeglądarki Playwrighta jednorazowo

pnpm exec playwright install chromium pobiera 118 MB, raz na maszynę. Wersja @playwright/test 1.64 (aktualna 25.10.2026), tylko Chromium na start.
