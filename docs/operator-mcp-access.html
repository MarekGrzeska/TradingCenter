Claude Code na narzędziach produkcji

Każda powierzchnia MCP produkcji odpowiada teraz jednemu klientowi z zewnątrz: Twojemu Claude Code. Przechodzi on przez trzy kontrole: token Entra, rolę admin i aplikację z listy. Od 27 października 2026 działa na produkcji: rejestracja Entra jest założona, PR #393 zmergowany i wdrożony. Zostało logowanie na każdej maszynie i kilka rzeczy do zrobienia raz (sekcja 05).

01 · Droga

Od Claude Code do narzędzia

Claude Code nie loguje się sam. Przed każdym połączeniem uruchamia scripts/mcp_token.py headers. Skrypt bierze token z pamięci podręcznej MSAL (Keychain) i wypisuje nagłówek Authorization. Krawędź (Caddy) tylko kieruje ruch i dopisuje znacznik X-TC-Edge. O tym, kto wchodzi, rozstrzyga sam proces.

03 · Decyzje

Co wybrałem i dlaczego

D1 · headersHelper zamiast wbudowanego OAuth działa dziś

Wbudowany OAuth Claude Code nie działa z Entra z dwóch powodów. Entra nie ma dynamicznej rejestracji klientów, a endpoint v2 odrzuca parametr resource, który wysyła Claude Code (AADSTS9010010, anthropics/claude-code#52871). Helper z MSAL omija oba problemy. Serwer nie musi przy tym publikować metadanych OAuth.

D1 · Własna rejestracja, nie az listy po aplikacji

Rejestracja app-tradingcenter-claude-code to klient publiczny pre-autoryzowany na obu API. az działałby bez Terraform, ale dostałby wtedy każde narzędzie, a log nie odróżniłby go od administrowania Telegramem. Odebranie dostępu Claude Code odbierałoby też ten drugi.

D2 · trading-mcp pod /trading na hoście API, z audiencją bramy bez DNS

Nie trzeba nowego hosta ani certyfikatu. Prawo do ruszania rachunku to admin na API bramy, to samo, którego terminal potrzebuje do zakładki z rachunkiem.

D3 · EdgeConfig.token_applications raz, w pakiecie

trading-mcp nie ma rekordu dostępu jak pakiety workbencha, więc lista wyliczonych aplikacji siedzi w drzwiach (tc-entra-auth). Pole jest domyślnie None, więc brama i workbench działają jak dotąd.

D4 · Zapisy z zewnątrz z śladem w logu słabszy niż baza

Rozmowa trzyma ślad zlecenia w bazie, a Claude Code omija rozmowę. trading-mcp nie ma bazy, więc zapisuje dwa wpisy trading_mcp.trace: przed wysłaniem i ze skutkiem, z aplikacją i osobą. Logi rotują (5 × 10 MB). Drugim śladem jest transkrypt Claude Code.

D5 · Osoba ustawiana w call_tool, nie w middleware zmierzone

W stanowym streamable-http narzędzie wykonuje się w zadaniu sesji, a nie żądania. Zmienna kontekstowa ustawiona wokół żądania HTTP tam nie dotrze. Podklasa FastMCP czyta więc osobę z żądania bieżącego wywołania. Test przechodzi przez prawdziwą sesję, a claude -p dostał asked_by: person-from-token.

D6 · Strategie zamontowane jak reszta odwraca D7

Jedynym powodem D7 było to, że operator nie ma klienta MCP. Teraz go ma. Zespoły dalej dostają tylko trzy narzędzia do odczytu. Backtest zlecony z Claude Code jest backtestem agenta, z tym samym limitem jednego naraz i tym samym licznikiem prób.

Na każdej maszynie, z której używasz Claude Code

Token i konfiguracja serwerów należą do maszyny, nie do repozytorium ani konta. Token leży w pęku kluczy systemu (na macOS w Keychain), a serwery w konfiguracji użytkownika Claude Code (~/.claude.json). Helper jest wpisany ścieżką bezwzględną do tego klonu repozytorium i do uv. Dlatego każda maszyna potrzebuje klonu repozytorium, uv i dwóch komend:

uv run --script scripts/mcp_token.py login \
  --tenant 1e076190-9713-407c-81dd-2da72233afd7 --client-id b19f77e3-c973-465e-83c2-6b80e5892962
scripts/claude-mcp.sh install api.57-129-181-251.sslip.io \
  1e076190-9713-407c-81dd-2da72233afd7 b19f77e3-c973-465e-83c2-6b80e5892962

Raz, dla całego systemu

Ansible na serwerze zrobione 27.10

Serwerowy /opt/tradingcenter/bin/deploy był z 14.10 i nie przeładowywał Caddy. Playbook uruchomiony z operator_user=ubuntu i ssh_allowed_cidrs=["0.0.0.0/0"], czyli z tym, co serwer ma dziś. Domyślne wartości odcięłyby SSH. Najpierw --check --diff: zmiana była jedna, ten plik. Od następnego deployu Caddy przeładowuje się sam.

Dryf w Terraform raz, przed następnym pełnym apply

Pełny terraform apply nadal chce zniszczyć admin_workbench i admin_gateway dla osoby 73c09587-…. Osoba ta ma rolę admin w stanie, a nie ma jej w lokalnym terraform.tfvars (admin_user_object_ids). Dopisz ją albo świadomie pozwól jej rolę zabrać.

Job plan w CI raz

terraform.yml pada na każdym PR z infra/ od 19.10: tożsamość CI nie może odczytać istniejącego delegated permission grant (Retrieving Delegated Permission Grant). Bez ochrony gałęzi niczego to nie blokuje, ale plan w PR jest przez to bezużyteczny. Brakuje uprawnienia Graph do odczytu grantów dla aplikacji CI.

Archiwizacja zmiany OpenSpec raz

06 · Pułapki

Co może zaskoczyć

„Dynamic Client Registration rejected (HTTP 401)” to nie awaria serwera

Tak Claude Code pokazuje helper, który odmówił, czyli brak zalogowania albo token odświeżania wygasły po około 90 dniach bez użycia. Rozwiązanie: mcp_token.py login. Helper nigdy nie loguje się sam, bo Claude Code daje mu 10 sekund.

Zapisy na rachunku bez śladu w bazie nie dopisuj do allowlisty

place_order, close_position, switch_active_account (zrywa strumień notowań archiwum) i send_telegram_message powinny zostać poza listą uprawnień Claude Code. Wtedy klient pyta za każdym razem.

Brak sufitu wywołań w turze obserwować

Sufit wywołań narzędzi z rozmowy nie obowiązuje Claude Code. Jedno wywołanie kosztuje bazę tyle samo co z rozmowy, ale pętla agenta może wołać częściej. Warto zajrzeć do prod-health po tygodniu.

Znalezione i naprawione przed commitem fixed

trading-mcp nie konfigurował logowania, więc każdy wpis INFO, w tym cały ślad zapisów, ginął na produkcji. Drugi problem: krok workflow wylicza nazwy zmiennych jawnie i nie podałby nowej. Wyłapał to test_assemble_env.
