Wskaźniki — testy lokalne

Scenariusze do przejścia ręką na działającym stosie, zanim gałąź add-technical-indicators pójdzie do main. Zadanie 7.4 zmiany OpenSpec — to, czego żaden test automatyczny nie sprawdza, bo dotyczy tego, co widać na ekranie.

Dotyczy: modules/market-data, modules/terminal
Zmiana: openspec/changes/add-technical-indicators, zadanie 7.4
Katalog w chwili pisania: 63 wpisy, sufit żądania 200 000 świec×wskaźników

Zanim zaczniesz

Trzy rzeczy, które psują przebieg, zanim się zacznie
  • Docker musi być wstały. Baza deweloperska to kontener z compose.yaml, 127.0.0.1:55432. Skrypt startowy podnosi go pierwszy — bez Dockera nie ruszy nic, nie tylko testy.
  • Jedna sesja demo Capital na całe konto. Drugi proces bramy wylogowuje pierwszy. Objaw: losowe 401 w obu. Nie uruchamiaj dwóch stosów naraz — także w drugim git worktree.
  • Pliki .env są per moduł i nie są w gicie. Skopiuj z .env.example. Brama potrzebuje CAPITAL_* i własnego GATEWAY_API_KEY; archiwum tego samego GATEWAY_API_KEY i DATABASE_URL. DATABASE_USER zostaje pusty — to on wybiera tryb lokalny.

Testy automatyczne — najpierw one

Ręczny przebieg ma sens dopiero, gdy to jest zielone. Komendy z katalogu modułu; w repozytorium nie ma niczego, co zbuduje albo przetestuje wszystko naraz.

Podniesienie stosu

./scripts/dev.ps1            # Windows
./scripts/dev.sh             # macOS, Linux
./scripts/dev.ps1 -NoTerminal   # sam back end (to, czego potrzebują testy live)

Kolejność jest wymuszona i każdy krok czeka, aż poprzedni odpowie, a nie aż zostanie uruchomiony: migracje → capital-gateway (8010) → market-data (8020) → terminal (5173). Porty są stałe.

Przed pierwszym scenariuszem potrzebna jest para z historią. W terminalu: Instruments → dodaj instrument (np. US100) i zbierz co najmniej kilka tysięcy świec na MINUTE — wskaźniki liczą się z serii, której nie ma, tak samo skutecznie jak z pustej.

Dlaczego akurat seria minutowa

time_profile, session_range_* i opening_range czytają serię drobną (MINUTE_5) niezależnie od tego, jaką rozdzielczość ma wykres. Bez niej odmawiają — i to jest poprawne zachowanie, nie awaria (scenariusz 15).

Bez terminala — odmowy i kształt odpowiedzi

Cztery rzeczy łatwiej sprawdzić na samym module. Poniżej PowerShell; market-data nie wymaga lokalnie żadnego klucza — to Easy Auth przed wdrożonym kontenerem, nie moduł.

TC-21 — katalog

$c = Invoke-RestMethod http://127.0.0.1:8020/indicators
$c.indicators.Count            # 63
$c.algorithm_version           # rośnie tylko przy zmianie wzoru, nie przy dodaniu wpisu
$c.indicators | Group-Object group | Select-Object Name, Count

TC-22 — policzenie i rozgrzewka

$body = @{
  resolution = "MINUTE_15"
  from = "2026-08-01T00:00:00Z"
  to   = "2026-08-05T00:00:00Z"
  specs = @(@{ id = "ema"; params = @{ period = 21 } }, @{ id = "atr" })
} | ConvertTo-Json -Depth 5

$r = Invoke-RestMethod -Method Post -ContentType application/json `
     -Uri http://127.0.0.1:8020/indicators/US100 -Body $body

$r.warmup_from                 # wcześniej niż `from` — moduł sam sięgnął wstecz
$r.results | Select-Object id, settled, warmup_bars
$r.times.Count                 # wspólna oś czasu dla wszystkich wyników
$r.uncovered                   # przedziały, których archiwum nigdy nie zweryfikowało

TC-23 — sufit żądania

# 10 wskaźników × zakres na tyle długi, żeby iloczyn przekroczył 200 000
$body = @{ resolution = "MINUTE"; from = "2020-01-01T00:00:00Z"; to = "2026-01-01T00:00:00Z"
           specs = @(@{ id = "ema" }) } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -ContentType application/json `
  -Uri http://127.0.0.1:8020/indicators/US100 -Body $body

Oczekiwane: 422 z detail nazywającym granicę — request exceeds the indicator ceiling of 200000 candles×indicators (~N asked for). Granica jest w odpowiedzi liczbą, nie ogólnikiem.

TC-24 — zakres odwrócony i nieznany wskaźnik

@{ resolution="MINUTE"; from="2026-08-05T00:00:00Z"; to="2026-08-01T00:00:00Z"; specs=@(@{id="ema"}) }
@{ resolution="MINUTE"; from="2026-08-01T00:00:00Z"; to="2026-08-02T00:00:00Z"; specs=@(@{id="nie_ma_takiego"}) }

Oczekiwane: oba 422, drugie z unknown indicator: 'nie_ma_takiego'. Wskaźnik z parametrem poza zakresem też — komunikat nazywa parametr i jego granice.

Co ten zestaw ma udowodnić

Że granica wobec strategii trzyma się kontraktu, a nie dyscypliny: żaden wynik nie jest wartością logiczną, każdy próg jest parametrem żądania powtórzonym w odpowiedzi, a nazwy jednej szkoły siedzą w aliases, nigdy w id. Sprawdź to na range_gap — niesie „Fair Value Gap" jako alias, nie jako identyfikator.

Co zostaje otwarte po tym przebiegu

Uczciwie, żeby nie było potem niespodzianki

Opóźnienie dopytywania nie zostało zmierzone na żywym stosie. design.md obiecywał pomiar przed wyborem między dopytaniem po zamknięciu świecy a osobną subskrypcją wskaźników; wybrano dopytanie na podstawie brzmienia zadania 6.1, bo w trakcie zmiany nie było działającego stosu do pomiaru. Scenariusz TC-19 pokazuje, że to działa — nie pokazuje, że jest dostatecznie szybkie na wolnym łączu. Przejście na subskrypcję nie rusza kontraktu, tylko sposób odpytywania.

Testy live zostają poza tym przebiegiem. uv run pytest -m live --run-live potrzebuje sesji demo, a --run-live-trading w bramie pisze — otwiera, zmienia i zamyka pozycje demo. Nigdy w CI, i nie przy okazji testu wskaźników.

Dokument roboczy do zadania 7.4. Po przejściu scenariuszy i wpisaniu wyniku do review.md traci rację bytu jako plan — zostaje jako zapis, co i jak było sprawdzone ręcznie. Prawdą o systemie są specyfikacje market-data-indicators, terminal-chart i terminal-grid.
